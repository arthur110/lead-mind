# lead_mind

面向旅游行业的 AI 内容获客工作台。

lead_mind 帮助运营人员发现游客需求、策划和制作内容、维护账号，并将咨询整理成可交给人工跟进的线索。人工负责后续销售转化，合作旅行社负责旅行服务履约。

> 当前状态：产品规划阶段。仓库目前保存项目说明，尚未实现应用、平台接入或可运行的部署版本。以下功能均为首版建设目标。

## 产品目标

- 将用户的真实问题转化为有依据的内容选题。
- 结合真实线路与素材，提高内容制作和日常运营效率。
- 汇总咨询、提取出游需求，减少人工整理和交接成本。
- 根据人工确认的有效线索，持续改进选题和内容。

首版主平台确定为小红书，聚焦一个旅游方向和少量自有账号，内容形式优先采用图文笔记。具体目的地待业务供给确定。

## 核心流程

```text
账号定位与日常运营计划
          ↓
小红书用户问题 / 参考笔记 → 需求机会卡 → 图文笔记草稿
                                        ↓
                                人工审核与小红书发布
                                        ↓
                                咨询收集与需求提取
                                        ↓
                                线索交接与人工确认
                                        ↓
                                效果反馈与选题调整
```

公开评论中的出游问题先进入待确认意向池。用户主动咨询或留下可跟进渠道后，进入线索处理流程。人工确认实际需求后，再统计为有效线索。

## 首版功能

| 模块 | 建设范围 | 主要产出 |
| --- | --- | --- |
| 账号与养号 | 小红书账号连接、定位资料、运营阶段、每日任务、内容节奏、登录与任务状态 | 账号运营计划与待办 |
| 需求与选题 | 导入小红书笔记链接和用户问题，归纳需求，生成并选择选题 | 需求机会卡与选题卡 |
| 素材与创作 | 上传真实素材和线路资料，生成图文笔记标题、正文、封面建议和配图顺序，人工编辑审核 | 可发布的图文内容包 |
| 发布任务 | 选择小红书账号、安排时间、发布提醒、记录笔记标识、链接与执行结果 | 发布台账 |
| 咨询与线索 | 收集可读取的评论及人工导入的私信咨询，提取需求、查重、分配、跟进与导出 | 有原始依据的线索卡 |
| 效果反馈 | 标记有效性及原因，关联来源内容，汇总获客结果 | 下一轮内容与运营建议 |

### 小红书接入顺序

以下是接入目标，尚未完成可用性验证。

1. **账号连接**：由用户本人完成登录，显示已连接、需重新登录和待处理状态，失败时给出明确提示。
2. **笔记参考与需求整理**：优先打通链接读取和可读取评论的整理，保留原文与来源；关键词搜索在接入验证后启用。
3. **图文发布**：人工审核标题、正文和图片后确认发布，保存笔记标识、链接及结果；连接不可用时提供人工发布任务与链接回填。
4. **咨询整理**：优先从自有笔记的可读取评论中发现咨询。私信先支持人工录入或粘贴，自动私信同步单独验证后再启用。
5. **线索反馈**：将咨询关联到账号和笔记，由人工确认有效性；来源无法确认时保持未知。

评论读取范围、登录保持、图文发布和数据回传需要用授权测试账号分别验证。对标笔记中的需求先进入待确认意向池，不能直接计为有效线索。每项自动接入都保留失败提示与人工补录入口。

## 养号与账号运营

养号功能围绕账号定位、稳定内容产出和真实咨询处理展开。

- **定位卡**：明确目标人群、目的地、核心话题、内容风格和资料完成情况。
- **运营阶段**：准备中、试运营、稳定运营、待处理，由人工确认阶段调整。
- **每日任务**：研究相关内容、整理用户问题、补充素材、制作发布内容、回复真实咨询。
- **内容节奏**：按实际产能设置每周内容计划和发布时间。
- **账号状态**：记录登录失效、发布失败和平台提示，暂停受影响任务并提醒处理。

运营效果通过发布稳定性、目标人群咨询和有效线索观察，不设置无法验证的账号权重分，也不承诺固定时间内获得流量。

## 需求发现与内容策划

需求发现通过“需求机会卡”与内容策划衔接。

| 对象 | 主要字段 |
| --- | --- |
| 需求机会卡 | 目标人群、出游场景、核心问题、决策障碍、原始来源、需求强度、待确认信息 |
| 选题卡 | 关联需求、内容角度、核心结论、所需素材、关联线路、内容形式、咨询引导 |

同一需求可以产生多个选题。策划优先考虑需求是否明确、与业务是否匹配、是否有真实素材和信息依据。新创意可以作为待验证假设进入内容计划。

例如，“带父母去云南，希望少换酒店”可以展开为路线选择标准、住宿安排对比和真实行程案例。发布后，将咨询与人工反馈关联回原需求，指导后续创作。

## 线索卡

| 字段组 | 内容 |
| --- | --- |
| 来源 | 平台、账号、作品或表单、首次咨询时间 |
| 出游需求 | 目的地、出发地、日期、天数、人数、预算、特殊要求 |
| 联系渠道 | 可继续沟通的平台会话，或用户主动提供的联系方式 |
| 需求证据 | 原始消息、已确认信息、AI 提取依据、待补充字段 |
| 跟进情况 | 负责人、当前状态、下一步、有效或无效原因 |

未提到的信息保持未知。跨平台记录仅在有可靠关联依据时合并，不仅凭相同昵称判断为同一人。

## AI 与人工分工

AI 负责需求归类、选题建议、内容草稿、素材整理、咨询摘要、回复建议和效果分析，并保留信息来源。

人工负责线路事实和服务承诺确认、对外内容审核、评论与私信发送确认、线索有效性判断，以及后续销售转化。旅行社负责最终履约。

## 工作界面

- **今日工作台**：账号状态、养号任务、待审核内容、发布任务和待处理咨询。
- **内容工作台**：需求、选题、素材、编辑审核和发布记录。
- **线索工作台**：原始咨询、需求摘要、负责人、跟进状态和有效性反馈。

账号设置和基础业务资料作为辅助页面。

## 首版验收与指标

首版应完成一条可追溯的小红书业务流程：连接一个自有账号，从用户问题生成选题，使用真实素材完成一篇图文笔记并发布；保存笔记链接，将收到的真实咨询整理成线索，交给人工判断；能查看来源笔记、有效性原因和下一轮内容调整建议。

外部接入验收应记录实际完成的操作、可读取的数据范围和失败处理方式。若试运营期间尚未收到真实咨询，可用明确标注的测试数据核验整理和交接功能，但不能据此认定获客效果已经验证。

主要观察指标：

- 人工确认的有效线索数。
- 有效线索率，即有效线索占已审核线索的比例。
- 每条有效线索的内容、工具与人工成本。
- 从收到咨询到负责人接收的时间。
- 需求提取准确性与人工修改量。
- 线索来源可追溯率，无法确认的来源保持未知。

## 后续扩展

在小红书首版流程验证后，再按实际需要增加视频笔记、持续对标监控、私信自动同步、更细致的内容实验，以及抖音、视频号等其他平台。批量自动评论与陌生私信不纳入首版。
