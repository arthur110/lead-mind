# lead_mind 首版需求说明 v0.1

更新日期：2026-11-06

状态：开发需求基线，功能尚未实现。

适用范围：小红书、旅游内容获客、本地运行、单运营人员。

## 1. 目标与产品边界

为旅游内容运营人员提供一个可持续使用的工作台，完成账号日常运营、需求整理、图文创作、发布记录、咨询整理、线索交接和反馈。

主要流程：

```text
账号定位 / 线路与素材资料
        ↓
参考笔记和用户问题 → 需求机会卡 → 选题卡 → 图文草稿
                                              ↓
                                       人工审核与发布
                                              ↓
                                       咨询记录与需求提取
                                              ↓
                                       线索卡与负责人认领
                                              ↓
                                       人工有效性反馈
                                              ↓
                                       更新后续选题和每日任务
```

首版重点是一个旅游方向、少量自有小红书账号、图文笔记。目的地由用户配置，不将云南等示例写成固定业务逻辑。人工负责销售转化，旅行社负责履约。

### 1.1 使用角色

- 运营人员：首版应用的唯一登录/使用主体，管理资料、账号、内容、咨询和反馈。
- 跟进负责人：作为可维护的姓名列表，用于分配线索和记录交接，首版不建设独立员工账号或权限系统。
- 旅行社：保存名称和线路资料，首版不建设供应商门户、订单、支付或结算。

### 1.2 优先级与完成边界

- P0：本文要求的本地业务流程、真实持久化、可用页面、AI 适配接口、小红书接入适配接口、错误提示与人工补录。
- 小红书真实接入：优先验证登录状态、笔记读取、可读取评论和审核后图文发布；逐项记录测试证据，缺少条件时标为未验证。
- P1：关键词持续监控、自动私信同步、视频笔记、多平台、复杂实验和精细成本分摊。
- 首版的定时功能是发布提醒和每日任务。到时间不自动发送内容；对外发布由用户明确点击确认。
- 养号采用定位、内容节奏、内容研究及真实咨询处理任务。首版不实现批量自动点赞、关注、陌生私信或账号注册。

## 2. 验收层次

必须分别报告以下三种结果，不能混淆。

| 层次 | 验收内容 | 通过条件 |
| --- | --- | --- |
| 本地业务流程 | 创建资料、草稿、审核、发布记录、咨询、线索、反馈 | 数据重启后保留；关联正确；人工路径可运行 |
| 外部服务接入 | 模型调用、小红书账号及已支持操作 | 使用实际服务验证；记录操作结果和能力限制 |
| 实际获客效果 | 真实内容产生真实咨询并由人工确认 | 有真实来源和反馈；演示数据不计入 |

没有模型密钥时，应用仍可手动完成业务流程，但 AI 按钮必须提示待配置；不能用固定文案伪装为模型生成。没有小红书连接时，应用提供人工发布、原文导入和结果回填，并明确显示未连接。

## 3. 页面与信息架构

页面默认中文，日期按 Asia/Shanghai 展示。数据库时间统一存 UTC。桌面优先，浏览器宽度不小于 1280px 时主要表格可直接操作；较窄窗口允许合理滚动。

| 页面 | 内容与主要操作 |
| --- | --- |
| 今日工作台 `/` | 账号异常、今日养号任务、待审核笔记、到期发布提醒、待处理咨询、未交接线索 |
| 账号与运营 `/accounts` | 账号列表、定位、阶段、周计划、每日任务、连接状态和可用能力 |
| 内容工作台 `/content` | 需求池、选题池、图文草稿、发布记录四个标签页；详情展示来源关系 |
| 线索工作台 `/leads` | 咨询收件箱、线索列表、原始消息、提取结果、交接和有效性反馈 |
| 资料库 `/library` | 线路资料和图片素材；支持新增、编辑、归档与筛选 |
| 设置 `/settings` | 跟进负责人、模型配置、平台连接配置、时区说明、数据导出入口 |

今日工作台汇总真实记录，不放随机数字或静态增长图。数据为空时提供明确的第一步，例如“添加账号”“添加线路”“导入一个用户问题”。

## 4. 核心业务对象

所有记录包含内部唯一 ID、创建/更新时间和 `data_mode`（live/demo）。两类数据禁止相互关联；默认统计仅包含 live。示例和测试记录具有持久化标记，不能只在页面上加提示。

| 对象 | 主要字段和约束 |
| --- | --- |
| Account 账号 | 平台固定 xiaohongshu；内部名称必填；平台用户 ID 可空；目标人群、目的地、内容定位、简介；运营阶段；连接状态；最近检查时间；连接配置引用 |
| Route 线路 | 名称、目的地必填；供应商、天数、适合人群、行程文本、包含/不含项目、限制、价格说明、价格有效期、资料确认状态；可归档 |
| Asset 素材 | 本地文件、原始文件名、类型、大小、内容哈希；目的地、标签、来源、使用权限（自有/已授权/仅参考/未知） |
| Source 原始资料 | 来源类型、来源链接、平台笔记/评论标识、账号关联、原始正文、作者公开标识（可空）、采集/发生时间、获取方式、数据范围说明 |
| Demand 需求机会 | 人群、场景、问题必填；障碍、需求强度、待确认字段；关联一个或多个 Source；状态观察中/可策划/已归档 |
| Topic 选题 | 标题、目标人群、要回答的问题、内容角度、核心结论、咨询引导；需求、账号、线路、素材关联；状态候选/已选择/已归档；标记证据型或待验证假设 |
| Draft 图文草稿 | 选题、账号、标题、正文、话题、按顺序排列的图片；版本号；状态；审核人、时间及审核版本；AI 生成记录引用 |
| Publication 发布记录 | 账号、草稿及版本快照、计划时间、方式（连接器/人工）、状态、平台笔记标识/链接、发布或确认时间、失败原因、人工回填标记 |
| Inquiry 咨询 | 来源类型、原文必填；账号、平台用户 ID、昵称、会话标识、时间、相关 Source 和 Publication；状态待处理/已建线索/仅作需求/已忽略及原因 |
| Lead 线索 | 一个或多个 Inquiry；出游字段及证据；可联系渠道；负责人；跟进状态；有效性；原始及最新来源；首建/分配/接收/首次联系时间；测试标记 |
| Task 运营任务 | 账号、日期、类型、标题、关联对象、状态待办/完成/跳过/受阻、原因、完成时间、幂等来源键 |
| FollowUp 跟进记录 | 线索、负责人、操作类型、说明、时间、下一步与到期时间 |
| Generation AI 运行 | 任务类型、输入对象及版本、模型、状态、时间、耗时、可获得的用量、错误类型；保存经验证的结果，不记录密钥 |

账号、线路、选题等被引用后采用归档方式，不能删除关联历史。草稿删除需确认，已发布快照不可覆盖。来源原文保持原样；人工修正需求字段另存，并记录修改时间。

## 5. 账号与养号功能

### F01 账号建立与连接

1. 用户填写内部账号名、目标人群、目的地和内容定位，保存账号。
2. 未连接时可使用计划、草稿及人工发布；不显示已登录。
3. 用户点击“连接/检查账号”，后端调用已配置的平台连接器。
4. 如需登录，展示连接器实际提供的登录入口，由用户本人完成；应用不收集小红书密码，不要求把 Cookie 粘贴到聊天中。
5. 检查成功后保存平台标识、昵称等必要摘要和验证时间。返回账号与已绑定账号不一致时提示确认重新绑定，不静默替换。

连接状态为未配置、未连接、已连接、登录失效、需人工处理、未知。网络错误只更新为未知或提示检查失败，不能据此断言账号被封。

首版可管理多个账号记录；每个连接器会话只绑定一个账号。若连接器仅支持一个登录会话，则只允许一个账号处于该连接器的活动绑定状态，不能宣称支持多账号并发操作。

### F02 日常运营计划

- 阶段：准备中、试运营、稳定运营、暂停。阶段由人工切换，独立于登录状态。
- 周计划：选择运营星期、计划发布时段、每周目标篇数。默认给出可编辑建议，不强制固定频率。
- 任务类型：完善定位、研究参考笔记、整理用户问题、补充素材、创作图文、审核发布、处理真实咨询、复盘。
- 点击“生成今日任务”时，根据计划和现有待办生成规则任务；同一账号、日期、来源对象及任务类型不能重复生成。
- 阶段为准备中时优先补资料；试运营和稳定运营围绕选题、创作、发布与咨询安排；暂停账号不生成新的执行任务。
- 账号失效只阻断需平台连接的任务，本地创作和资料整理仍可进行。
- 任务支持完成、跳过和受阻，后两种需填写原因；补录过往任务保留真实操作时间。
- 应用启动或进入今日工作台时生成缺失任务，首版不依赖常驻定时器。错过日期不补发内容。

可选 AI 建议用于解释计划和推荐任务，用户确认后写入。养号进度用任务完成情况、发布记录和咨询反馈呈现，不生成账号权重分或封号概率。

## 6. 需求与内容功能

### F03 线路与素材资料

- 线路支持表单编辑和粘贴行程文本；AI 可提出结构化整理草稿，用户确认后保存。
- 价格是可选字段，必须同时保留价格说明和有效期；未确认或已过期价格不得直接进入可审核通过的价格文案。
- 首版图片仅支持 JPEG、PNG、WebP，每张不超过 20MB，校验真实文件类型；此为本产品初始限制，不作为平台规则。
- 素材上传支持多选、预览、排序和标签，文件存本地受控目录，数据库存相对路径。按内容哈希避免重复存储。
- 仅参考、未知权限素材可用于选题研究，必须替换为自有或已授权图片后才能通过发布审核。
- 首版提供封面建议、图片选择与顺序调整，不要求建设图片编辑器、AI 生图或视频制作能力。

### F04 需求导入与归纳

入口包括“导入笔记链接”和“粘贴用户问题/正文”。链接读取失败时保留链接并让用户补充原文，不能伪造读取结果。短链接只交给受限连接器解析，普通后端不能任意抓取用户提交的 URL。

用户选择若干原始资料后点击“分析需求”。AI 返回一个或多个需求草稿，包含人群、场景、核心问题、障碍、需求强度、待确认信息及 Source 引用。用户可编辑、合并、选择保存。

- 需求强度枚举：一般兴趣、具体问题、比较方案、主动询价。
- 原文没有的信息保存空值；例如“春节”保留原始表达，不能自动认定年份和具体日期。
- 对已有需求提示可能相似的主题，首版由人工决定合并，不做全库自动聚类。
- 相同平台原始 ID 重复导入时复用记录；无 ID 时只对同账号、同来源、同原文的重复导入提示，不能跨用户自动合并。
- 需求机会的“证据数量”仅统计独立来源，重复导入不能提高证据数量。

### F05 从需求生成选题

需求卡提供“生成选题”“补资料”“继续观察”三个操作。

生成选题时输入选定需求、账号定位、候选线路和可用素材摘要，默认提出三个不同角度，如判断标准、方案对比、真实案例。输出包括标题、要回答的问题、核心结论、形式、素材需求、关联线路和咨询引导。

运营可选择或编辑一个选题，其他候选保留。不存在真实案例素材时，只能标记“需补充案例”，不能生成虚构游客经历。手工新增选题允许没有需求来源，但必须标为“待验证假设”。

### F06 图文创作与审核

创建草稿需选择账号和选题；选择线路可选，但提及价格、行程或服务承诺时必须关联已确认的相应资料。编辑区包括标题、正文、话题、图片顺序及封面选择，右侧显示笔记预览和来源资料。

AI 根据选题、真实线路和素材生成标题候选、正文草稿、封面文字建议、配图顺序和待确认项。生成结果先作为候选显示，用户选择“应用”后才替换编辑区，不能覆盖生成期间的人工修改。

草稿状态：`draft → pending_review → approved`。退回修改回到 draft。审核通过前检查账号、非空标题/正文、至少一张可发布图片，以及未处理的事实确认项。

- 修改标题、正文、话题、图片或目标账号时版本递增，原审核失效，回到 draft。
- 审核保存版本及内容快照；模型再次生成同样不能沿用旧审核。
- 已发布内容只展示快照；要制作新版本时复制为新草稿，不修改历史发布内容。
- 标题、图片数量等平台限制由连接器能力或已核验配置提供，不编造平台限制；违反已知限制时给出具体字段提示。
- 所有事实确认项由人工逐项处理，处理结果记录在审核中。

## 7. 发布功能

### F07 发布提醒与结果记录

一份草稿对应一个目标账号。跨账号复用通过复制草稿实现。用户可为已批准版本设置计划时间，今日工作台按 Asia/Shanghai 显示到期提醒。改动草稿后，旧版本待发布任务自动失效。

发布状态独立于草稿状态：`scheduled / ready / publishing / published / failed / unknown / cancelled`。

**连接器发布路径**

1. 用户点击“发布”，查看账号、最终内容与图片摘要，再点击“确认发布”。
2. 服务端再次校验当前版本仍获批准，并创建唯一请求键；同一发布请求只允许一个执行任务。
3. 平台明确返回成功时保存笔记 ID/链接；返回成功但无可定位结果时记为 unknown，待核对。
4. 超时或连接中断且无法确认平台是否已发布时记为 unknown，禁止自动重发；允许检查结果或人工填写已发布链接。
5. 明确失败时保留错误和恢复操作。平台要求验证时暂停相关账号的平台任务并提示用户处理，不循环重试。

**人工发布路径**

1. 用户下载或复制经过审核的内容包，在小红书完成发布。
2. 回填笔记链接和发布时间，确认所发布内容对应这个版本。
3. 保存为 published，标记方式为人工、结果为人工确认；不伪装成系统自动核验成功。

仅支持已知小红书域名的笔记链接或经连接器验证的解析结果。相同账号与笔记 ID/规范链接重复回填时复用已有发布记录或提示冲突。

首版外部发布不因 AI 输出、到达计划时间、任务重试或页面刷新自动触发。复制图文或下载内容包不能记为已发布。

## 8. 咨询与线索功能

### F08 咨询收件箱

入口包括读取指定自有笔记可获取的评论、手工粘贴私信/评论、手工录入其他咨询。首版不要求建立公开表单服务。

- 咨询原文必填；账号、来源类型和发生时间必须明确，无法确认的可标记未知。
- 自动读取须保存采集时间、分页或读取范围说明，不将部分评论标成全量同步。
- 评论来源 ID 存在时按账号、笔记 ID、评论 ID 去重；手工重复粘贴给出提示，由人工确认。
- 详情页同时展示原始消息、来源笔记和 AI 提取结果；可补充同一咨询的后续消息。
- 原文删除或平台链接失效不破坏已保存的业务记录，并提示原链接当前可能不可用。
- 对标笔记中的讨论保存为需求来源，不直接自动建立可跟进线索。

### F09 需求提取与建档

点击“提取出游需求”后，AI 输出目的地、出发地、日期原文及可确认日期、天数、成人/儿童人数、预算及口径、特殊需求、咨询意图、缺失信息和每个字段的原文证据。

示例“我们两大一小，预算一万”可提取成人 2、儿童 1；预算 10000 的口径若原文不明确，保存为未知，不推定人均或总额。低置信度或有歧义的字段突出显示，用户可以手工确认。

线索建立至少要求：一条原始咨询、一项明确的旅游问题或需求，以及可继续沟通的平台会话/用户渠道或用户主动提供的联系方式。电话不是必填项；只有泛兴趣且无法继续沟通的内容保留为需求信号。

已有人为确认的字段不能被后续 AI 自动覆盖，新增冲突展示为待确认建议。昵称相同不自动合并。同平台稳定用户标识相同可提示同一联系人，但不同出游计划可以保留为不同线索。合并线索必须人工确认并保留全部咨询和来源。

### F10 分配、跟进与有效性反馈

跟进状态：待分配、待接收、跟进中、已结束。有效性单独维护：待判断、有效、无效。

- 分配必须选择负责人并保存时间；“已接收”单独记录接收时间，不能以分配时间替代。
- 人工录入首次联系、需求补充和下一步，首版不自动发送团队通知、邮件或私信。
- 标为有效时须确认有实际出游需求、可跟进渠道，且与当前业务服务范围基本匹配；允许预算尚未确定。
- 标为无效或已结束时填写原因，可选无出游计划、重复咨询、服务不匹配、无法继续沟通、其他并补充说明。
- “已结束”不自动代表成交；首版不追踪订单或佣金。
- 状态修改记录历史；重新打开记录不能清除首次接收和联系时间。
- 提供可复制的人工交接摘要及 CSV 导出，导出仅含选定线索及必要字段。

### F11 来源归因

每条咨询可关联一篇已发布笔记，也可保持未知；一条线索可累计多个咨询来源。保留首个已知来源与完整来源列表。

笔记详情展示关联咨询数和去重线索数，同一线索在同一笔记内只计一次。账号和全局统计按线索 ID 去重，不把各笔记数字简单相加。无法定位来源的私信不得强行分配给最近发布的笔记。

## 9. 效果反馈

首版工作台显示真实计数、简单表格及近 7/30 天筛选：

- 已发布笔记数：按实际或人工确认发布时间。
- 新增咨询数和线索数：按各自记录创建时间；重复导入不新增计数。
- 有效线索数：选定创建时间范围内线索的当前有效性为有效的数量。
- 有效线索率：同一线索创建时间范围内，有效数 /（有效数 + 无效数）；无已判断线索时显示“暂无已审核线索”。
- 来源可追溯率：同一线索范围内至少有一个明确来源内容的线索数 / 总线索数；无数据时显示“暂无数据”。
- 交接耗时：从最早已关联咨询的已知发生时间，到首次接收时间；时间缺失或先后异常时不计算并提示补录，展示有效样本数。

线索成本是业务目标。首版可手工记录周期总成本，以同周期获客线索的当前有效数计算估算成本；成本缺失显示“未录入”，不能显示零成本；有效数为零时显示“暂无法计算”。标明数据会随人工审核更新，不宣称精确归因。

复盘页面可调用 AI 生成下一轮建议，输入仅为真实统计和已记录反馈。样本少时明确说明证据有限，不自动断言某选题导致高转化。建议经人工选择后进入选题池或任务计划。

## 10. AI 服务约定

### 10.1 首版任务

`extract_demand` 归纳需求；`suggest_topics` 推荐选题；`draft_note` 生成图文；`extract_inquiry` 提取出游需求；`draft_reply` 草拟回复；`review_results` 复盘建议。

规则每日任务、查重约束、计数和状态变更使用确定性业务逻辑，不依赖模型自由判断。模型只生成候选，不直接修改发布状态或线索有效性。

### 10.2 输入输出规则

- 模型配置在服务端读取，支持可配置的服务地址、模型和密钥；默认可采用兼容常见聊天补全格式的文本服务，具体请求格式须在开发时核对实际服务文档。
- 每类任务定义结构化结果 Schema，验证字段类型、枚举、必填项和引用 ID。
- 事实型字段带 `value`、`evidence_source_id`、`evidence_text`、`confidence`；无依据返回 null。引用 ID 必须来自输入，证据文本应存在于对应原文。
- 旅游预算包含金额、币种和口径；不明确的部分为 null。日期同时保留原文和规范化结果，不能编造年份。
- 将外部笔记、评论及线路文本视为资料，不把其中的指令当作系统操作指令。
- 输入到模型的咨询应移除不必要的联系方式和标识；联系方式由本地业务记录管理。
- 模型超时或结构校验失败时显示可理解的错误，保留人工输入并允许重试；不能返回假成功。
- 生成请求记录输入版本；结果返回时若内容已改变，只显示候选和版本冲突提示。
- 用量缺失时记为未知，不估算成零；首版不要求精确计费账单。

### 10.3 演示模式

测试可用固定模型输出和模拟平台连接器，必须显式启用 demo 模式，并在界面持续显示“演示数据”。演示模式不能调用真实发布操作，不能计入真实指标。上线或首次正常启动默认不加载演示数据。

## 11. 小红书连接器契约

连接器是 lead_mind 后端可实际调用的服务或适配代码，不能假设开发时的 Codex 工具在独立应用中自动可用。不得把未核验的接口地址或响应格式当作已实现平台 API。

建议接口：

| 操作 | 输入 | 输出要求 |
| --- | --- | --- |
| capabilities | 连接配置 | 登录检查、登录入口、笔记读取、评论读取、图文发布、发布结果查询、搜索分别是否支持及已知限制 |
| check_session | 连接引用 | 状态、实际账号摘要、检查时间 |
| begin_login | 连接引用 | 实际登录入口、二维码或明确的不支持状态；不采集密码 |
| read_note | 来源链接 | 平台笔记 ID、作者公开摘要、正文、可用媒体引用、读取时间 |
| read_comments | 笔记引用、游标或读取限制 | 评论列表、平台 ID、作者标识、已知发生时间、下一页信息、是否完整及原因 |
| publish_note | 已审核版本、账号引用、唯一请求键 | 成功/失败/结果未知、笔记 ID/链接、平台错误 |
| get_publish_result | 请求引用或平台标识 | 已核实结果或不支持状态 |

状态至少包含 `UNSUPPORTED`、`AUTH_REQUIRED`、`VERIFICATION_REQUIRED`、`RATE_LIMITED`、`NETWORK_ERROR`、`REMOTE_ERROR`、`UNKNOWN_RESULT`。限流和验证需要暂停并提示处理，不能切换账号反复尝试。发布确认结果未知时不可自动重发。

首个真实适配实现前，应检查可用的小红书工具或服务，并记录其来源、支持能力和认证要求。接口能力不足时保留明确的人工路径，交付报告列出未完成的自动接入项。

## 12. 本地架构与工程约束

为减少首版决策成本，建议采用以下默认方案；这是本项目拟定的开发约束，不代表依赖已安装或验证。实现时核对依赖当前官方文档并锁定实际版本。

- 前端：React + TypeScript + Vite，中文桌面工作台。
- 后端：Python + FastAPI，统一提供本地业务 API、AI 调用和平台连接器调用。
- 数据：SQLite + SQLAlchemy，带数据库迁移；图片存本地 `data/uploads/`。
- 执行：数据库记录任务状态，单进程后台任务即可。首次启动、重启、任务失败都要可恢复；不为首版引入消息队列或分布式调度。
- 运行：默认只监听 127.0.0.1，按本机单用户工具交付；共享部署、多租户和公网登录另行设计。
- 数据访问：前端经后端读写数据库，不把 localStorage 作为业务数据源。
- 凭据：服务端环境变量或系统钥匙串；设置页面仅显示是否配置和脱敏摘要。Token、Cookie、密钥不得出现在浏览器持久化、日志、导出或 Git 中。
- API 写入只允许配置的本地前端来源，校验 Host/Origin；不使用通配跨域，不开放未认证的公网访问。
- 上传校验类型、大小和路径，文件名不作为实际存储路径；导入外链限制目标域名及重定向，拒绝本地/内网目标。
- CSV 导出处理以 `= + - @` 等开头的文本，防止表格软件执行公式。
- `.gitignore` 应覆盖 `.env`、凭据、数据库、上传文件、日志和依赖目录；提供不含真实密钥的 `.env.example`。

建议目录：

```text
apps/web/                  前端页面与交互
apps/api/                  后端业务、数据库与服务
apps/api/app/integrations/  模型和小红书适配器
apps/api/tests/             业务规则与接口测试
tests/e2e/                 本地端到端验收
docs/requirements/         产品需求
docs/integrations/         实际接入能力与验证记录
data/                      运行数据，不进入 Git
```

首版必须有保存成功/失败、空数据、加载中、输入错误、连接失效等状态。错误不应导致表单清空。耗时请求展示进行中和结果；后台任务在重启后对未确认发布标记为 unknown，本地生成任务标记为中断并允许重试。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |

## 14. 建设顺序与交付要求

1. 初始化工程、数据库、配置、错误处理与演示隔离；实现账号和资料库。
2. 实现原始资料 → 需求 → 选题 → 草稿的手工流程和真实保存。
3. 接入模型，完成结构化验证、版本冲突保护和生成记录。
4. 实现审核、发布提醒、人工发布回填与发布幂等状态。
5. 实现咨询 → 线索 → 人工接收及有效性反馈，补齐查重和归因。
6. 实现养号任务和基于真实数据的今日工作台、复盘统计。
7. 完成可用小红书连接器的真实适配，逐项验证能力并记录限制。
8. 完成关键业务测试与端到端测试，补充运行说明和交付报告。

交付必须包含可运行代码、数据库迁移、脱敏配置样例、启动步骤、演示模式说明、测试结果、已实现/未实现清单、真实接入验证记录。不得用演示页面或模拟响应替代实际功能完成声明。

开发时可细化实现方式，但影响上述业务行为、数据定义或对外动作的变更需先说明。需求与 README 冲突时，以本文件的首版细则为准，并同步修正 README。
